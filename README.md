# Raspberrypi DShot

DShot ESC output for the Raspberry Pi, generated by the SoC's **Secondary
Memory Interface (SMI)**. It maps the GPIO, SMI and clock-manager registers
through `/dev/mem`. Root is required.

## Requirements

- **Board**: a Raspberry Pi with BCM2835, BCM2836, BCM2837 or BCM2711
  (Pi 1/Zero, Pi 2, Pi 3/Zero 2 W, Pi 4). Not the Pi 5: it has no SMI.
- **Checked on**: Pi 4 (frames read back bit for bit at DShot150/300/600),
  Zero 2 W.
- **Root**, for `/dev/mem`.
- **`dtoverlay=smi` off.** With it the kernel driver owns the SMI block and
  init refuses to run.

## Specifications

### Summary

| | |
|---|---|
| DShot speeds | DShot150, DShot300, DShot600, DShot1200 |
| Pins | GPIO 8-25 (SMI data lines SD0-SD17), any subset, any order |
| Channels | 1-8 motors. All go out in one SMI transfer, so every frame starts on every pin at the same instant |
| Values | 0 = MOTOR_STOP, 48-2047 = throttle. Telemetry bit 0; the 4-bit checksum is added by the library |
| Samples per DShot bit | 7 (T0H 28.6 %, T1H 71.4 %), 3 (33.3 % / 66.7 %) or 4 (25 % / 75 %) |
| Repeat | none: one frame per call, the caller sends at its control rate |
| Highest send rate | one frame per frame time: about 9 kHz at DShot150, 18 kHz at DShot300, 37 kHz at DShot600, 74 kHz at DShot1200 |

### Pins and SMI width

The highest pin in use sets the SMI bus width. A whole frame has to fit the
SMI FIFO (64 words on the boards checked, measured at every init), and
narrower widths pack more samples into a word. Unless told otherwise
(`DshotConfig.samples_per_bit` in `dshot_init()`), the library takes the
first of 7, 3, 4 samples per bit that fits:

| Highest pin | SMI width | Samples per FIFO word | Samples per bit | Frame |
|---|---|---|---|---|
| GPIO 8-15  | 8  | 4 | 7 | 28 words |
| GPIO 16-23 | 16 | 2 | 7 | 56 words |
| GPIO 24-25 | 18 | 1 | 3 | 48 words |

Only the pins passed to init become SMI outputs; the other GPIOs keep their
function. SPI0 sits on GPIO 7-11.

### Timing per board

A sample is a whole number of SMI clocks, and the SMI clock is PLLD divided
by an integer 2-15, so the bit time lands slightly off the nominal one. The
tables are for 7 samples per bit (pins up to GPIO 23).

#### PLLD 500 MHz (BCM2837: Zero 2 W, Pi 3)

| | Divider | Clocks per sample (setup+strobe+hold) | Sample | Bit (nominal) | T0H | T1H | Frame |
|---|---|---|---|---|---|---|---|
| DShot150  | 14 | 34 (8+18+8) | 952 ns | 6664 ns (6667) | 1904 ns | 4760 ns | 106.6 µs |
| DShot300  | 14 | 17 (4+9+4)  | 476 ns | 3332 ns (3333) |  952 ns | 2380 ns |  53.3 µs |
| DShot600  |  7 | 17 (4+9+4)  | 238 ns | 1666 ns (1667) |  476 ns | 1190 ns |  26.7 µs |
| DShot1200 |  6 | 10 (2+6+2)  | 120 ns |  840 ns (833)  |  240 ns |  600 ns |  13.4 µs |

#### PLLD 750 MHz (BCM2711: Pi 4)

| | Divider | Clocks per sample (setup+strobe+hold) | Sample | Bit (nominal) | T0H | T1H | Frame |
|---|---|---|---|---|---|---|---|
| DShot150  | 14 | 51 (12+27+12) | 952 ns   | 6664 ns (6667) | 1904 ns | 4760 ns | 106.6 µs |
| DShot300  |  7 | 51 (12+27+12) | 476 ns   | 3332 ns (3333) |  952 ns | 2380 ns |  53.3 µs |
| DShot600  |  2 | 89 (22+45+22) | 237.3 ns | 1661 ns (1667) |  475 ns | 1187 ns |  26.6 µs |
| DShot1200 | 10 |  9 (2+5+2)    | 120 ns   |  840 ns (833)  |  240 ns |  600 ns |  13.4 µs |

#### Where PLLD comes from

PLLD is read from `/sys/kernel/debug/clk/plld_per/clk_rate`. When that is
not readable, 500 MHz is assumed (750 MHz on BCM2711), and the self-test
frame at init catches a wrong guess. Init prints what it set up; a Pi 4 at
DShot300 with motors on GPIO 17, 12, 23, 13:

```
dshot: init OK  DShot300  7 samples/bit  width 16 (2/word)
  sample 476.000 ns  bit 3332 ns (T0H 952, T1H 2380)  frame 53312 ns  (PLLD 750 MHz / 7, setup 12 strobe 27 hold 12)
  FIFO 64 words (TXD drops at 62), frame 56 words, SMI_L 112, self-test frame 53703 ns
  pins: GPIO17=SD9 GPIO12=SD4 GPIO23=SD15 GPIO13=SD5
```

## Using the library

### Build

Include `dshot_esc.h` and compile `dshot_esc.c` and `dshot.c` into the
program:

```
gcc -O2 -Wall -o myprog myprog.c dshot_esc.c dshot.c
```

`dshot_esc.h` is the per-motor interface (`esc_proto_*`). `dshot.h` is the
lower layer, which takes one array of DShot values per frame.

### Rules

- **Nothing repeats on its own.** Every `apply`/`arm`/`stop` puts exactly
  one frame on the wire, so the caller keeps calling at its control rate,
  also while idle. An ESC that stops seeing frames stops the motor.
- **A skipped frame returns 1.** `esc_proto_apply()` returns 1 when the
  previous frame was still going out and this one was skipped. Called slower
  than one frame time that never happens.
- **One context, one sending thread.** Only one `esc_proto_init()` context
  may exist at a time, and the sends have no lock.
- **Which calls suit a real-time thread.** `esc_proto_apply()`,
  `esc_proto_arm()` and `esc_proto_stop()` make no syscalls.
  `esc_proto_init()` and `esc_proto_deinit()` do, and `deinit` sleeps, so
  call those two from a normal thread.
- **Dry run.** `esc_proto_set_dry_run(true)` before init runs the SMI
  without switching the pins.

### Example: four motors in a control loop

Condensed from `examples/quad_example.c`. Left out: includes, option
parsing, the `on_signal()` handler that sets `s_stop`, `timespec_add_ns()`,
and `motor_value()`, which stands for the flight controller's mixer (the
full example holds every motor at one value given with `-f`).

```c
#include "dshot_esc.h"

#define N_MOTORS  4
#define LOOP_HZ   2000

static const int MOTOR_GPIO[N_MOTORS] = { 17, 12, 23, 13 };   /* GPIO 8-25 */

int main(void)
{
    signal(SIGINT, on_signal);
    mlockall(MCL_CURRENT | MCL_FUTURE);
    struct sched_param sp = { .sched_priority = 80 };
    sched_setscheduler(0, SCHED_FIFO, &sp);

    /* 1. Init: maps the registers, self-tests the SMI, sends one MOTOR_STOP. */
    EscProtoCtx *esc = esc_proto_init(ESC_PROTO_DSHOT300, MOTOR_GPIO, N_MOTORS);
    if (!esc) return 1;

    const long period_ns = 1000000000L / LOOP_HZ;
    const long arm_ticks = 3 * LOOP_HZ;                 /* 3 s of MOTOR_STOP */
    struct timespec next;
    clock_gettime(CLOCK_MONOTONIC, &next);

    for (long tick = 0; !s_stop; tick++) {
        if (tick < arm_ticks) {
            /* 2. Arming: the ESC arms on a steady stream of MOTOR_STOP. */
            esc_proto_arm(esc);
        } else {
            /* 3. Every control tick: the mixer outputs, then one frame. */
            for (int m = 0; m < N_MOTORS; m++)
                esc_proto_set(esc, MOTOR_GPIO[m], motor_value(m));  /* 0 or 48-2047 */
            esc_proto_apply(esc);
        }
        timespec_add_ns(&next, period_ns);
        clock_nanosleep(CLOCK_MONOTONIC, TIMER_ABSTIME, &next, NULL);
    }

    /* 4. Exit: MOTOR_STOP for 50 ms, then the pins go low. */
    esc_proto_deinit(esc);
    return 0;
}
```

Build and run the full example:

```
make example
sudo ./quad_example -y -d 5     # dry run: the SMI runs, the pins are not switched
sudo ./quad_example -f 0.05     # propellers off: 5 % throttle after arming, Ctrl-C stops
```

## Bench tool

`dshot_test` checks a board, the pins and an ESC before the library goes
into a program.

### Quick start

```
make
sudo ./dshot_test -y -d 3 12 13     # 1. dry run, DShot300: pins untouched, safe on any board
sudo ./dshot_test -l 12 13          # 2. nothing attached to GPIO 12/13: must end in "loopback: PASS"
sudo ./dshot_test -t 150 12         # 3. ESC on GPIO 12, propellers off: arms 3 s, then value 150; Ctrl-C stops
```

DShot300 is the default; add `-s 150`, `-s 600` or `-s 1200` for another
speed.

### Command line

```
sudo ./dshot_test [options] <gpio> [<gpio> ...]
```

`<gpio>` is one GPIO number (8-25) per motor, 1 to 8 of them, separated by
spaces.

#### Options

| Option | Meaning | Default |
|---|---|---|
| `-s <150\|300\|600\|1200>` | DShot speed | **300** (DShot300) |
| `-r <hz>` | frames per second | 4000 |
| `-t <value>` | DShot value sent after arming: 0 (MOTOR_STOP) or 48-2047 | 0 |
| `-a <sec>` | how long MOTOR_STOP is sent before `-t` takes effect | 3 |
| `-d <sec>` | run time, then stop | until Ctrl-C |
| `-y` | dry run: the SMI runs, the pins are not switched | off |
| `-l` | loopback check, then exit (cannot go with `-y`) | off |

`-r` has to leave at least 20 µs between frames, so the highest rate is
about 7.8 kHz at DShot150, 13.6 kHz at DShot300, 21 kHz at DShot600 and
29 kHz at DShot1200. A higher rate is refused at start.

#### Exit status

| Code | Meaning |
|---|---|
| 0 | done |
| 1 | bad option, or init failed |
| 2 | loopback failed |

### Test steps

#### Step 1: dry run (any new board)

Sets up and self-tests the SMI and sends frames, but the pins keep their
function, so it is safe with anything attached.

```
sudo ./dshot_test -y -d 3 17 12 23 13
```

A Pi 4 prints:

```
dshot: init OK  DShot300  7 samples/bit  width 16 (2/word)
  sample 476.000 ns  bit 3332 ns (T0H 952, T1H 2380)  frame 53312 ns  (PLLD 750 MHz / 7, setup 12 strobe 27 hold 12)
  FIFO 64 words (TXD drops at 62), frame 56 words, SMI_L 112, self-test frame 53833 ns
  dry run: pins not switched, nothing reaches the header
DShot300   (value 48-2047)
value 0 after 3.0 s of MOTOR_STOP, 4000 Hz
[   1 s] sent 4000 skipped 0 | apply 3.6/3.7/13.6 us | late max 112 us | fifo_err 0 stall 0
[   2 s] sent 4001 skipped 0 | apply 3.6/3.7/3.8 us | late max 45 us | fifo_err 0 stall 0
```

- `init OK` means every init check passed. Without it the reason is on
  stderr and the tool exits with 1.
- `bit` / `T0H` / `T1H` / `frame` are the timing actually generated for the
  chosen `-s`.
- The once-a-second line shows frames `sent` and `skipped` (previous frame
  still going out), the time one `esc_proto_apply()` took (min/avg/max), how
  late the loop woke up after its tick at worst (`late max`), and the SMI
  error counters. `skipped`, `fifo_err` and `stall` should stay 0.

At the end it prints the totals and the SMI registers.

#### Step 2: loopback (pins with nothing attached)

Drives the pins and reads them back through the GPIO level register while
test frames go out, then decodes each pin's 16 bits by high time. The test
frames carry a wrong checksum on purpose so that an ESC would ignore them,
but nothing should be connected.

```
sudo ./dshot_test -l 12 13
```

```
loopback: reading GPIO levels back while frames go out (expect T0H 952 ns, T1H 2380 ns, bit 3332 ns)
  set 1, 188 ns per sample, 1 try
    GPIO12 sent 0xA5C0  read 0xA5C0  T0H 975  T1H 2403  bit 3350 ns  ok
    GPIO13 sent 0x3C97  read 0x3C97  T0H 879  T1H 2376  bit 3336 ns  ok
  set 2, 186 ns per sample, 1 try
    GPIO12 sent 0x5A3F  read 0x5A3F  T0H 929  T1H 2433  bit 3343 ns  ok
    GPIO13 sent 0xC368  read 0xC368  T0H 1011  T1H 2415  bit 3343 ns  ok
loopback: PASS
```

Set 2 is the complement of set 1, so every bit of every pin is checked as
both a 0 and a 1. `read` has to equal `sent` on every pin. The measured high
times are only as fine as the read loop (about 190 ns per sample here), so
they wander by about one sample around the expected ones. This checks the
bit pattern; it does not measure jitter. It is firm up to DShot600 and too
coarse for DShot1200, where the tool prints a warning.

#### Step 3: one ESC and motor (propellers off)

```
sudo ./dshot_test -t 150 12                 # DShot300: MOTOR_STOP for 3 s, then value 150
sudo ./dshot_test -s 600 -t 150 -d 10 12    # DShot600, stop after 10 s
```

The first 3 s (`-a`) are MOTOR_STOP so that the ESC arms; then every motor
gets the `-t` value. With a non-zero `-t` the tool prints a warning that the
motor will spin. Ctrl-C or the end of `-d` sends MOTOR_STOP for 50 ms and
leaves the pins low.

## How it works

### Why SMI and not DMA to GPIO

DShot can also be drawn by DMA control blocks that write the GPIO set/clear
registers, but those place every edge on a 1 µs grid. A DShot300 bit is
3.33 µs with high times of 1.25 / 2.5 µs, so the edges fall between grid
points and jitter, and DShot600 (1.67 µs bit) is out of reach.

The SMI is a parallel bus master meant for external memories and displays.
In write mode it shifts words out of a FIFO onto data lines SD0-SD17
(GPIO 8-25, function ALT1) at a cycle time set by its own clock, in steps
of a few nanoseconds. Each motor gets one data line, so a sequence of bus
words is the DShot waveform of every motor at once.

### Bit time: clock divider and setup / strobe / hold

One SMI write cycle lasts `setup + strobe + hold` SMI clocks, and the data
lines hold their value for the whole cycle. That cycle is one *sample*. At
init the library:

1. takes the nominal bit time (1 / kbit) divided by the samples per bit;
2. tries dividers 15 down to 2 of PLLD for the cycle length in clocks that
   comes closest (slower clocks win ties; cycles of fewer than 8 clocks only
   when nothing longer fits);
3. splits it as `setup = hold = clocks / 4` and `strobe = the rest`, and
   writes that with the bus width into the device 0 settings
   (`SMI_DSR0`/`SMI_DSW0`).

A DShot bit is then a run of samples: the first ones high on every pin, the
middle ones high only on pins sending a 1, the rest low. With 7 samples that
is 2 + 3 + 2, so a 0 is high for 2/7 of the bit and a 1 for 5/7.

### Why 7 samples per bit

Bluejay reads a 0 only for a high time of 20-37.5 % of the bit, about
333-625 ns at DShot600. The 37.5 % often quoted for DShot sits on the upper
edge of that window and is read as a 1 once the edges stretch it slightly;
the frame then fails its checksum and the ESC never arms. 2/7 (28.6 %) puts
a 0 in the middle of the window, with room on both sides for slow edges and
noise from a running motor.

### Sending a frame

Every send:

1. builds each motor's 16-bit frame: 11-bit value, telemetry bit 0, 4-bit
   XOR checksum;
2. expands the frames MSB first into samples, one bit per pin in each sample
   (bit `gpio - 8`), and packs 4, 2 or 1 samples into each FIFO word
   (`PXLDAT` on for widths 8 and 16);
3. writes the whole frame into the FIFO through `SMI_D`, and only then sets
   `START`. The transfer count `SMI_L` is set once at init to one frame.

Since the whole frame is in the FIFO before the transfer starts, nothing has
to keep up with the bus while it runs and no other bus traffic can stretch a
sample. If the previous frame is still going out the send is skipped and
counted. A transfer still busy long past a frame time is aborted and
replaced by an all-low frame.

### Checks at init

`dshot_init()` (and so `esc_proto_init()`) refuses to run unless every check
passes, and only then switches the pins to the SMI function:

- the SoC is BCM2835/2836/2837/2711 (the peripheral base is read from the
  device tree) and the kernel SMI driver does not own the block;
- the SMI clock starts and the settings are accepted;
- the FIFO depth is measured and a frame fits;
- a frame loaded without `START` stays in the FIFO;
- an all-low test frame starts and finishes, and its time is compared with
  the computed frame time (a mismatch is printed as a warning).

Until then the pins are plain outputs driven low, and on exit they go back
to that.
